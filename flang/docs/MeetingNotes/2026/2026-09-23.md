# Community Call 2026-09-23

* Design docs and/or RFCs
  * [\[RFC\]\[Flang\]\[DebugInfo\] Inconsistent GDB Breakpoint Behavior for Fortran \`ENTRY\` Procedures](https://discourse.llvm.org/t/rfc-flang-debuginfo-inconsistent-gdb-breakpoint-behavior-for-fortran-entry-procedures/91767/1)
    * Discussion continues on Discourse
  * [Cross-compilation of real(kind=16)](https://discourse.llvm.org/t/cross-compilation-of-real-kind-16/89161)
    * PR has been posted: [https://github.com/llvm/llvm-project/pull/221907](https://github.com/llvm/llvm-project/pull/221907)
    * This will be a change to the compiler’s behavior, previously execution would error unconditionally but with this PR execution will now continue if the platform supports quad-precision arithmetic even if a library containing quad-precision intrinsics is not available
    * Idea: move the error as early as possible, even into compile time error
      * Counterpoint: can not detect at compile time if the library is available on the target machine, this needs to remain a linker error
    * Please put comments on the PR, the author can not attend the calls due to timezone issues
  * [Removing or reducing redundant messages in Integration tests](https://discourse.llvm.org/t/removing-or-reducing-redundant-messages-in-integration-tests/91591)

  * From Themos Tsikas via Slack : how do we handle potential data races in the compiler?
    * [https://flang-compiler.slack.com/archives/C5C58TT32/p1790077626135249](https://flang-compiler.slack.com/archives/C5C58TT32/p1790077626135249)
    * Possibility of introducing sanitizers to Flang
      * Using common tools already available in LLVM
    * Converging on opinion that the default mode of the compiler will be to seek maximum performance assuming the requirements of the standard are satisfied
    * Capture this idea in the documentation so it is visible to the users?
  * [\[flang\] Module files incorrectly expose implicitly recognized intrinsics · Issue \#219570](https://github.com/llvm/llvm-project/issues/219570) / Intrinsic accessibility depends on compilation layout
    * Could make Flang consistent with gfortran, but there is a conflict with how the two compilers behave and are not mutually portable
    * What behavior should we standardize to and what does the Fortran standard say?
      * The NAG compiler accepts both variants that are originally in the issue, several other compilers (Cray, Intel) do so as well
      * The standard could use some clarification on the specific concerns, should ask the committee for an interpretation
