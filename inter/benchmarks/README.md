# Lighthouse performance comparison

This benchmark compiles the same `128x128x64` f16-to-f32 matmul through Inter
and Lighthouse's original MLIR-to-XeVM pipeline, validates repeated launches,
and compares Level Zero kernel timestamps using identical `2x2` workgroups of
256 threads.

Configure Inter with hardware integration enabled, build the benchmark, and run
the orchestration script:

```sh
cmake -S inter -B inter/build -G Ninja \
  -DMLIR_DIR=$PWD/build-m0/lib/cmake/mlir \
  -DLLVM_DIR=$PWD/build-m0/lib/cmake/llvm \
  -DINTER_INCLUDE_INTEGRATION_TESTS=ON
ninja -C inter/build inter-opt inter-translate inter-lighthouse-benchmark
export PYTHONPATH=/path/to/llvm/install/python_packages/mlir_core
python3 inter/benchmarks/lighthouse.py --build-dir inter/build
```

The default Lighthouse checkout is `~/llvm/lighthouse`. It must be at revision
`ec3a77574cc5f049736f47b121bdd4aeeb854201`, which generated the Inter input.
Override the checkout or Python executable with `--lighthouse-root` and
`--lighthouse-python`. The selected Python environment and `PYTHONPATH` must
provide Lighthouse's dependencies and the matching MLIR Python bindings.

The Lighthouse binary is regenerated by `examples/xegpu/matmul.py` with the
requested shape and the original `64x64x32` workgroup schedule, including its
`16x16` subgroup tiles and one-block A/B prefetch. The pipeline stops at
`--dump-kernel=final` with `--no-accumulate-c`. The benchmark extracts the
native object from the emitted `gpu.binary`; there is no separately authored
OpenCL kernel.

Defaults are five alternating Inter/Lighthouse runs. Each run performs 200
validated warmup launches followed by 15 batches of 1,000 timestamped launches.
Use `--runs`, `--warmups`, `--batches`, and `--iterations` for shorter
experiments. Each compiler run has a 120-second timeout; override it with
`--timeout`.
Inputs are deterministic dense `{-1, 0, +1}` matrices. Validation combines
1,024 exact CPU dot products, complete finite/integer/output-bound scans, two
independent Freivalds projections, and canaries around C. Between timed batches,
an untimed launch writes a freshly poisoned C allocation; another untimed launch
restores GPU residency after host validation.
The default runtime device substring is `B60`. Override it with `--device` when
targeting a different GPU architecture supported by both generated binaries.

Use `--size 256` (or another multiple of 64) to scale the square M/N dimensions
while retaining `K=64` and the same `64x64` workgroup tile. This isolates grid
scaling from reduction-loop scaling.

Use `--reduction-size 256` (or another multiple of 32) to scale K independently.
The script specializes the Inter input and asks Lighthouse to regenerate its
MLIR pipeline for the same shape.

Use `--padding-k-tiles 1` to extend the physical A/B allocations without
changing their logical block2D descriptor dimensions.
